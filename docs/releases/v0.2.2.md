# Envoix v0.2.2

Envoix v0.2.2 is the ECE4410J demo release. It packages the current cross-platform transfer clients and command-line tools from one tagged source revision.

## Downloads

- Android: `envoix-android.apk` — arm64-v8a + x86_64, test-signed release build.
- macOS: `Envoix-macOS.zip` — Universal arm64 + x86_64 application, ad-hoc signed and not notarized.
- iOS/iPadOS: `Envoix-iOS.ipa` — development-signed archive for registered devices; TestFlight remains the preferred Apple distribution path.
- Windows: `Envoix-Desktop-Windows-x86_64.exe` and `envoix-cli-windows-x86_64.exe`.
- Linux: `Envoix-Desktop-Linux-x86_64` and `envoix-cli-linux-x86_64`.
- macOS CLI: `envoix-cli-macos-aarch64` and `envoix-cli-macos-x86_64`.
- `SHA256SUMS` authenticates the downloadable artifacts listed by the release.

## Highlights

- Unified Room, transfer, and Nearby surfaces across Apple and Android clients.
- Windows and Linux graphical demo clients are now published alongside the CLI.
- BLE verification uses the built-in rendezvous and relay endpoints when the corresponding Apple settings are left blank.
- Android release packaging passes unit tests, lint, shrinking, and native-library packaging gates.

## Known limitations

- BLE discovery and six-digit verification are experimental. A verified first connection can still fail while opening Room control, and remembered-room reconnect may time out. For the most reliable demo, use QR, a complete invitation, or Room Code instead of BLE first-pairing.
- The Windows/Linux graphical client is a focused demo client: it does not provide the full mobile Nearby, settings, persistence, or resume experience.
- The macOS build is ad-hoc signed and not notarized. Do not disable Gatekeeper globally; use the per-app **Open Anyway** flow only after verifying `SHA256SUMS`.
- The Android APK uses the project test key. Uninstalling an older build to resolve a signing mismatch clears its local app data.
- The GitHub iOS IPA is not a public App Store package and only installs on devices covered by its development provisioning profile.
