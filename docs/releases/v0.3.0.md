# Envoix v0.3.0 — release notes draft

Status: preparation only. No public v0.3.0 release has been published.
The release owner is [moranxuege/envoix](https://github.com/moranxuege/envoix).

## What changes

- Persistent transfer tasks with pause/resume controls, recovery, received-file
  management, and live progress across native Apple/Android and desktop clients.
- A Windows GUI integrated with the CLI and background Agent, plus Linux/WSL
  CLI and Agent workflows.
- Persistent device trust and explicit receiver confirmation after validation
  and saving. Desktop tasks continue independently of the GUI window.
- Versioned release bundles with SHA-256 manifests, dependency SBOMs, and
  GitHub build provenance tied to one immutable source revision.
- Android APK/AAB signing with a new long-term production identity. Both
  `arm64-v8a` and `x86_64` are included; version code is `5`.

## Upgrade before installing

v0.3 uses Engine state schema 2. Keep received files and back up old state;
follow [the migration and recovery guide](../v0.3/operations.md) to reset old
product state and re-pair devices. Switching from an old Android test key to
the production key may require uninstalling the old app, which clears app data.
Do not assume an in-place upgrade is supported across signing identities.

## Candidate evidence and open distribution work

The complete non-publishing release rehearsal passed at
`2cdce5f5a75c729a81477cc4476fed87195857b1`. Independently downloaded bundles
passed 18 checksum and 20 provenance/SBOM checks. This evidence applies to that
revision; the final release must record its own exact source revision.

- macOS app: an earlier universal Developer ID build was notarized and stapled
  successfully on September 5. The latest candidate still needs notarization
  after restoring the notarytool credential profile.
- iOS/iPadOS: distribution identities/profiles are valid; final archive/export,
  TestFlight installation, and physical-device acceptance are outstanding.
- Windows: no Authenticode certificate or signing service is configured.
  Publisher signing is explicitly deferred; SmartScreen and foreground
  picker/send acceptance must be documented.
- Real-device, retained-state, and upgrade coverage remains a release gate.
